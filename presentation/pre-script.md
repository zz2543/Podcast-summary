# GotIt · Pre 口述稿（9 章版）

**总时长**：约 8–9 分钟 · 1 封面 + 9 正页
**用法**：每页一段，可直接读；`/` 略停换气，**加粗**重读。

## 封面（10 秒）

大家好，/ 我们这一组今天讲的项目叫 **GotIt**。/ 这是一个**本地跑的**播客摘要工具，/ 你给它一个链接，/ 十分钟之后，/ 它把一小时播客压成几分钟就能看完、/ 三十秒就能听完的浓缩。/ 接下来我用九页讲完它。

---

## P1 · 背景（45 秒）

先讲为什么做这件事。/

播客时长通常是 40 到 90 分钟，/ 听完一集成本很高。/ 用户最常问三个问题：/ 这一集到底讲了什么？/ 值不值得我花一小时？/ 哪些段落值得回头再听？/

我们看了现有的工具：/ Otter 太重，/ YouTube 自动字幕没有章节，/ 直接转录稿信息又不浓缩。/ 都不顺手。/

所以我们的定位很直接：/ **给一个链接，/ 拿回 hook 一句话、/ 三幕结构、/ 章节、/ 引用、/ 命名实体，/ 再加一段 30 秒能听的 TTS 浓缩。**

---

## P2 · 我们学到的（60 秒）

做完这个项目，/ 我们留下四件事。/

**第一**，/ 先写规范再写代码。/ 我们没有上来就敲键盘，/ 而是写了 12 份 spec 文档，/ 加 5 条项目宪法，/ 走 spec → plan → tasks → code 这个顺序。/

**第二**，/ AI 不是答案，/ 是协作伙伴。/ 我们一会儿讲的 6 个 hard-won bug，/ 没有一个是 AI 一上来就能告诉我们的。/ 都是去读响应、/ 读协议、/ 读数据库**自己查**出来的。/

**第三**，/ trade-off 是工程的本质。/ 这是本地自用工具，/ 我们刻意**不上** Redis、/ Celery、/ Postgres，/ 但每一层都给扩展留了口子。/

**第四**，/ 测试是护栏，/ 不是 KPI。/ domain 模块覆盖率 80% 是硬门，/ 每修一个 bug 同步加一个回归测试。

---

## P3 · 功能边界（45 秒）

这一页讲清楚我们**做什么、不做什么**。/

**做了的**：/ 本地文件、/ 直链、/ YouTube、/ B 站都能输入；/ 中英文 ASR、/ hook、/ 三幕、/ 章节、/ 引用、/ 实体全都有；/ 引用可以毫秒级点击跳原音频；/ 30 秒 TTS 浓缩；/ Markdown、/ JSON、/ MP3 一键导出；/ 进度通过 WebSocket 实时推送。/

**v1 不做的**：/ 不做多用户、/ 不做公网部署、/ 不做实时直播流、/ 不做视频画面分析、/ 超过 6 小时或 1 GB 的输入会被拒绝、/ 也不做收费 SaaS。/

约束很明确：/ 单用户、/ 127.0.0.1 回环、/ 单进程 asyncio、/ SQLite 加本地文件。

---

## P4 · 前端（60 秒）

前端我们做了**两套并行的 UI**，/ 共享同一个后端。/

v1 跑在 5173，/ 纯 CSS，/ 功能优先。/ v2 跑在 5174，/ 用 Tailwind 加 framer-motion，/ 走 Apple Liquid Glass 风格。/ 两套同时跑，/ 看哪个**自己用着更舒服**。/

详情页是我们花最多时间打磨的一页。/ 有四个细节：/

**一**，/ hook 大字引用，/ 30 字内一句话，/ 看一眼就知道这集讲什么。/
**二**，/ 原音频播放器 sticky，/ 滚动时永远在顶。/
**三**，/ 章节里的引用块**可以点击**，/ 时间戳是按字符在段内的位置**线性插值**算出来的，/ 点一下原音频立刻 seek、/ 自动播放、/ 滚动跟随。/
**四**，/ AI Digest 播放按钮做了流动彩虹渐变，/ 和黑色的原音频按钮**一眼区分**。

---

## P5 · 后端 · 一条 8 段流水线 + 前后端连接（75 秒）

后端最有料的部分是一条**8 段流水线**。/ 我顺着箭头扫一遍：/

**第一步 fetch**，/ yt-dlp 把音频拉下来，/ ffmpeg 转 mp3；/
**第二步 transcribe**，/ 豆包 ASR，/ 拿到带时间戳的转录；/
**第三、四、五步**都是 DeepSeek 跑摘要：/ hook 一句话、/ 三幕、/ 章节 outline；/
**第六步 quote-verify**，/ 这一步是我们**自己写的**，/ 等会儿讲 bug 时回来说；/
**第七步 entities**，/ 抽人名、/ 书名、/ 产品名；/
**第八步 export**，/ 出 Markdown 和 JSON。/

TTS 是**独立的子 pipeline**，/ 按按钮才触发，/ 不阻塞主流程。/

---

后端真正想讲的**四个工程决策**：/

**一**，/ 每个 stage **独立 retry**。/ 用 tenacity 指数退避，/ 单步抽风**不会**让整条作业从头重来。/
**二**，/ 进度**落盘**。/ `stage_progress` 表写 SQLite，/ 进程重启**可以继续**。/
**三**，/ 状态变化通过**事件总线**广播到 WebSocket，/ 前端看到哪一步在跑、/ 哪一步死了。/ **不是轮询**。/
**四**，/ 单进程 asyncio。/ 我们**没上** Celery、/ 没上 Redis。/ 本地够用，/ 加这些反而是负担，/ 但每一层留了扩展口。/

---

前后端怎么连？/ 一句话：/ **HTTP 调度生命周期，/ WebSocket 推进度**。/ 生产模式下 `make serve` 让 FastAPI 把 SPA 和静态产物一并出。/ 所有协议都在 `contracts/` 目录里有明确契约，/ 不靠默契。

---

## P6 · 接入的外部 API · 我们调了谁（45 秒）

这一页讲我们**调了哪些外部服务**。/

**ASR 语音识别**，/ 用的是**豆包 Seed-ASR 2.0**，/ 火山引擎。/ 不是一次性接口，/ 要 submit 再 query 轮询。/ 本地上传走 flash 端点。/ 回退方案有 Whisper 和 Qwen。/

**LLM 摘要**，/ 默认是 **DeepSeek Chat**，/ OpenAI 兼容协议。/ Hook、/ 三幕、/ 章节、/ 实体都是它跑。/ 回退是 Qwen 和 Anthropic Claude。/

**TTS 浓缩音频**，/ 用的是**豆包 BigTTS 2.0**，/ 资源 ID 叫 `seed-tts-2.0`。/ **它没有简单的 HTTP 接口**，/ 只有 WebSocket 二进制双向流。/ 这一层协议是我们**自己实现**的，/ 不是调一个 pip 包。/ 回退是豆包 v1 和 Qwen CosyVoice。/

外加两个工具：/ **yt-dlp** 下 YouTube 和 B 站，/ **ffmpeg** 做音频归一化。/

最后一点：/ 三个 provider 都有抽象工厂，/ **改一行 env** 就能切，/ 调用代码完全不动。

## P8 · Bug · 已解决 / 未解决（90 秒 · **重点**）

这一页是我们**最想讲**的。/ 6 个 bug，/ 没有一个是 AI 直接吐给我们的。/

**一**，/ TTS 一直 401。/ 后来发现豆包的 Authorization 头**要用分号**，/ 不是空格。/ 这不是 OAuth 标准。/
**二**，/ TTS 报 max len，/ 单次只能 1024 字节。/ 我们写了按 utf-8 字节切句拼装的函数。/
**三**，/ 这个最坑。/ BigTTS 一直说"concurrency exceeded"，/ 我们以为是并发满了。/ 查文档才发现，/ resource_id 应该是字符串 `seed-tts-2.0`，/ 不是数字编号。/ **错误信息完全在误导**。/
**四**，/ digest.mp3 是空文件，/ 没报错。/ 因为这一集语言被标成 mixed，/ 中文内容路由到了英文音色，/ 服务端**静默丢弃**。/ 静默失败比报错可怕。/
**五**，/ 多条 quote 显示同一个时间戳。/ 旧算法只返回段起点。/ 我们改成**按字符位置线性插值**，/ 时间戳精确到秒，/ 同步加了一个回归测试。/
**六**，/ Retry 时 worker 直接崩。/ unique 约束撞车 → session rollback → 后续 query 全挂。/ 我们补了清理函数加测试。/

**未解决的部分**也讲清楚：/ 5 集真实播客的人工准确率没跑、/ M2 上 60 分钟样本的耗时没 benchmark、/ 多语言混合的同语言摘要还要优化、/ 豆包云端 smoke fixture 待补、/ 前端 Playwright E2E 还没接。
